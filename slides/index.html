Planteamiento del Problema • Machine-to-Machine

El Dilema: ¿Por qué las IAs no pueden comerciar solas hoy?

Los Modelos de Lenguaje (LLMs) hoy razonan y llaman APIs. Sin embargo, en la economía digital abierta son fantasmas sin identidad soberana, sin billetera verificable y sin reputación resistente a trampas.

⚠️
El Problema Actual (Web2)
• Falta de Cédula Universal: No se puede distinguir entre un agente legítimo y un clon.

• Ataques Sybil (Reseñas Falsas): Un desarrollador malicioso crea 10,000 bots para autocalificarse con 5 estrellas.

• Falta de Descubrimiento de Capacidades: Si una IA quiere contratar a otra, no hay un protocolo estándar para saber qué herramientas expone.
💡
La Solución: ERC-8004 + MCP
Diseñado por MetaMask, Ethereum Foundation, Google y Coinbase:

• ERC-8004: Provee el pasaporte NFT de identidad, la reputación firmada y la validación en hardware seguro.

• Model Context Protocol (MCP): Estandariza la forma en que el agente anuncia sus funciones y las ejecuta para otros clientes.
Diseño Modular • Tres Registros Singleton

Pilar I • Seguridad y Gobernanza

Separación de Poderes: Owner vs Operational Hot Wallet

En producción, nunca se debe dejar la clave legal del agente en el servidor de IA. ERC-8004 establece una estricta separación:

1. Propietario Legal (Owner / DAO / Humano)
• Dueño del NFT ERC-721 registrado en ownerOf(agentId).
• Custodiado en una Hardware Wallet (Ledger) o multisig.
• Es la única cuenta autorizada a actualizar la Agent Card o transferir el agente.
2. Billetera de Trabajo (Operational Hot Wallet)
• Clave privada que corre en el proceso de la IA.
• Firma peticiones diarias, transacciones en Sepolia y emite recibos feedbackAuth.
• Si el servidor es atacado, el atacante no puede robar la propiedad del agente.
contracts/IdentityRegistry.sol Solidity 0.8.24 
// Separación en el registro de identidad
function registerAgent(
    string calldata agentURI,
    address operationalAddress
) external returns (uint256) {
    _agentIdCounter++;
    uint256 newAgentId = _agentIdCounter;

    // El NFT se acuña al Owner (msg.sender)
    _safeMint(msg.sender, newAgentId);
    _setTokenURI(newAgentId, agentURI);

    // La hot wallet queda asociada para trabajo
    _agentAddresses[newAgentId] = operationalAddress;

    return newAgentId;
}
Pilar II & III • Confianza Verificable

Reputación Anti-Sybil y Validación Criptográfica

El Candado feedbackAuth (Reputación)
• Anti-Autoelogio: El smart contract revierte si msg.sender == owner o la operationalWallet.

• Firma Criptográfica Obligatoria: Para calificar a una IA, el cliente debe presentar un recibo firmado por la clave de trabajo del agente:
digest = keccak256(cliente, agentId, taskHash)

• Resultado: Es matemáticamente imposible inflar calificaciones con bots falsos.
Validación en Enclaves TEE / zkML
• Para Tareas Críticas: Cuando una IA mueve liquidez en Uniswap o diagnostica código, la reputación no basta.

• El Validador TEE (Intel SGX): Un nodo independiente re-ejecuta el algoritmo en hardware sellado y emite validationResponse(100, TEE-ATTESTED).

• Auditado en el Taller: Nuestro nodo zkSepolia-IntelSGX-Enclave-01 certifica la exactitud matemática.

Resolución de Metadatos • Disponibilidad Permanente

El Secreto del Agent Card: ¿Por qué `{}` en 8004scan?

Al registrar un agente con ipfs://bafybeif..., el explorador mostraba un JSON vacío {}. Veamos el diagnóstico técnico y la solución de ingeniería:

El Problema del Gateway IPFS
Si el CID de IPFS no está anclado (*pinned*) activamente en nodos con alta disponibilidad, los gateways de 8004scan dan timeout (404) y devuelven {}.
La Solución: Data URI Base64 On-Chain
Codificamos el JSON en data:application/json;base64,... y llamamos a setAgentURI(11287, dataURI). Los datos quedan grabados en el almacenamiento de Ethereum, sin servidores externos y con ~79k gas de actualización.
scripts/update-card.js Actualización en Caliente 
// 1. Leer src/agentCard.json
const card = JSON.parse(fs.readFileSync("src/agentCard.json"));

// 2. Codificar en Data URI RFC-2397
const dataUri = "data:application/json;base64," +
  Buffer.from(JSON.stringify(card)).toString("base64");

// 3. Invocar setAgentURI en Sepolia (~79,000 gas)
await canonicalContract.setAgentURI(11287, dataUri);
// ✔ 8004scan actualiza en tiempo real de inmediato
Integración LLM • Model Context Protocol

Cómo Conectar la MCP al Agente ERC-8004

El protocolo MCP (Model Context Protocol) es el puente entre el razonamiento de la IA y la ejecución técnica. En la Agent Card se declaran dos componentes clave:

1. El Bloque de Servicios (Endpoint de Transporte)
Indica dónde está escuchando el agente para peticiones MCP:
"services": [{ "name": "MCP", "endpoint": "http://localhost:3001/sse" }]
2. Catálogo de Herramientas y Schemas (tools)
Declara las 4 herramientas disponibles con sus tipos Zod / JSON-Schema:
• analyze_liquidity_pool (DEX, Pair, TVL, Slippage)
• verify_contract_safety (Auditoría on-chain Sepolia)
• get_sepolia_token_metrics (ERC-20 metrics)
• get_agent_passport (Consulta de identidad ERC-8004)
src/agentCard.json Definición Oficial de Herramientas 
"mcp": {
  "protocolVersion": "2024-11-05",
  "transport": { "type": "sse", "url": "http://localhost:3001/sse" },
  "tools": [
    {
      "name": "analyze_liquidity_pool",
      "description": "Analiza liquidez y slippage en Uniswap v3 Sepolia.",
      "inputSchema": {
        "type": "object",
        "properties": { "pair": { "type": "string", "default": "WETH/USDC" } }
      }
    },
    {
      "name": "get_agent_passport",
      "description": "Consulta pasaporte on-chain en 8004scan.",
      "inputSchema": { "properties": { "agentId": { "type": "number" } } }
    }
  ]
}
Infraestructura de Servidor • src/mcp/server.mjs

Cómo Servir la MCP: Arquitectura SSE & STDIO

Hemos construido un servidor MCP de grado de producción en src/mcp/server.mjs usando el SDK oficial @modelcontextprotocol/sdk. Soporta dos modos de operación:

Modo 1: Servidor Web HTTP / SSE (Producción en Red)
• Comando: bun run serve:mcp
• GET /sse: Abre el stream Server-Sent Events para clientes remotos.
• POST /messages: Procesa el protocolo JSON-RPC 2.0 (tools/list, tools/call).
• GET /tools & /health: Inspección REST rápida para pruebas.
Modo 2: Canal STDIO (Integración con IDEs)
• Comando: bun run serve:mcp:stdio
• Conecta por stdin/stdout directamente a Claude Desktop, Cursor o Antigravity.
src/mcp/server.mjs Servidor MCP Oficial 
import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
import { SSEServerTransport } from "@modelcontextprotocol/sdk/server/sse.js";
